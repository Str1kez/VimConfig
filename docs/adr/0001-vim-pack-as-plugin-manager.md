# Плагины через vim.pack, не через lazy.nvim

Управление плагинами перевели на встроенный в Neovim 0.12 `vim.pack` вместо
`lazy.nvim`. Причина — предыдущая переустановка конфига держалась на
`packer.nvim`, который в какой-то момент архивировали и его пришлось выпиливать
целиком; хотелось убрать этот класс риска, а не поменять один внешний
менеджер на другой. `vim.pack` — часть ядра, архивировать некому, обновляется
вместе с самим nvim.

Цена решения: нет декларативного lazy-loading (`event`/`cmd`/`ft`/`keys`, как
у lazy.nvim) — всё, что добавлено через `vim.pack.add`, грузится при старте.
При 13 плагинах в этом конфиге это не ощущается. Если список сильно вырастет
или появится что-то тяжёлое — возвращаться к вопросу заново, возможно в пользу
lazy.nvim или ручного lazy-loading через autocommands.

## Considered Options

- **lazy.nvim** — зрелый, живой (активен на момент решения), есть
  lazy-loading и UI. Отклонён: это снова внешний плагин одного автора — ровно
  та конструкция, что подвела с packer.
- **Оставить как есть, только заменить архивные плагины** — минимальный риск,
  но конфиг остаётся в 2023 году и продолжает тащить пакетный менеджер,
  который сам может повторить судьбу packer.
